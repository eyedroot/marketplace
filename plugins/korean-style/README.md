# korean-style

- 공적인 문서의 어휘와 지나친 압축을 걷어내고, 동료에게 말하듯 읽히는 한국어를 쓰게 만드는 output style plugin

## 무엇을 고치려는 것인가

- 한국어가 어색해지는 자리를 두 가지로 본다
  - 공적인 문서에서 쓰는 어휘를 끌어옴
    - 기술 문서라고 판단하면 어휘의 층을 한 단계 올리게 됨
    - `신설`, `보장`, `소관`, `기인`은 그 판단의 결과물이지 원인이 아님
  - 뜻을 한 단어와 긴 명사구에 몰아넣음
    - 쓰는 쪽에서 아낀 만큼 읽는 쪽이 도로 풀어야 함
- 막을 단어를 외우는 방식으로는 해결되지 않음
  - 열 개를 막으면 열한 번째가 나옴
  - 실제로 v0.1.0을 어떤 저장소에 걸어 교정했더니, 바뀐 60줄이 전부 목록에 적어 둔 세 항목이었음
  - 목록 밖에 있던 268자짜리 문장은 손대지 않은 채 남았음
- 그래서 목록이 아니라 판단 기준을 둔다
  - 어휘: **"이 단어를 옆자리 동료에게 말로 설명할 때 그대로 쓰겠는가"**
  - 압축: **"읽는 사람이 이 문장을 한 번에 이해하는가"**

## 포함된 output style

- `plain-korean`
  - 문체를 어디에 맞출지 한 줄로 고정
    - 옆자리 동료에게 설명하는 자리이지 보고서도 공문도 아님
  - 두 원인을 나눠서 다룸
    - 어휘는 판단 기준과 어긋났던 사례 몇 개
    - 압축은 판단 기준과 셀 수 있는 신호
  - 예시는 금지어 목록이 아니라 판단이 어긋난 자리로 적음
    - 목록에 없는 단어도 같은 기준으로 보게 하기 위함
  - 이미 쓴 글을 고칠 때의 순서를 따로 둠
    - 문장 구조를 먼저 보고 어휘를 나중에 봄
    - 순서를 뒤집으면 구조 교정이 통째로 빠짐
  - `keep-coding-instructions: true`
    - Claude Code의 코딩 지침은 그대로 유지됨
  - 적용하지 않는 자리
    - 코드, 변수명, 함수명
    - 코드 주석, 커밋 메시지, 로그 문자열
    - 인용, 오류 메시지, 명령어, 설정 키, 파일 경로

## 포함된 검사 도구

- `scripts/check_korean.py`
  - 셀 수 있는 것만 센다
    - 압축은 문장 길이와 절의 개수로 드러나므로 오류로 잡음
    - 어휘는 사례 몇 개밖에 못 잡으므로 주의로만 알려 줌
  - 검사를 통과해도 글이 자연스러워진 것은 아님
    - 도구가 안심시켜 주는 역할만 하지 않도록 요약 줄에 매번 적어 둠
- 사용법
  ```bash
  python3 scripts/check_korean.py 문서.md
  python3 scripts/check_korean.py 문서.md --quiet
  echo "테이블 4개 신설" | python3 scripts/check_korean.py -
  python3 scripts/check_korean.py --rules
  ```
- 오류로 보는 것
  - 한 문장이 120자 이상
  - 쉼표 3개 이상인 문장에 주어 표지가 2개 이상
    - 나열 도중에 절이 바뀌어 어디까지가 한 묶음인지 읽어서는 알 수 없는 문장
  - 가운뎃점, 점 연산자, 엠대시, 이모지
  - 영문 뒤에 떨어진 조사
- 주의로 보는 것
  - 한 문장이 80자 이상, 쉼표 6개 이상, 조사 `의` 3회 이상
  - 판단이 어긋났던 어휘 사례
- 같은 항목이 4건 이상 반복되면 한 줄로 묶어서 보여 줌
  - 표기 실수 수십 건이 목록을 채워 문장 구조 문제를 덮는 것을 막기 위함
- 검사에서 빼는 자리
  - 화살표가 들어간 줄
    - 고치기 전후를 함께 보여 주는 예시로 봄
  - 백틱으로 감싼 부분
    - 코드이거나 단어 자체를 가리키는 자리로 봄
    - 조사 띄어쓰기를 볼 때는 백틱만 떼고 안쪽 글자는 남김
  - 코드 블록 전체
- 종료 코드
  - 오류가 있으면 `1`, 주의만 있거나 깨끗하면 `0`
  - 훅이나 CI에 걸 때 이 값을 보면 됨

## 쉼표로 갈아 끼우기만 하면 안 되는 이유

- 가운뎃점이 작은 묶음을, 쉼표가 큰 묶음을 가르고 있던 문장이 있음
  ```
  원래:      권한은 최고관리자·관리자가 생성·편집·저장·취소·재발급·삭제, 운영자는 조회(URL 확인)만이다.
  단어만 바꿈: 권한은 최고관리자, 관리자가 생성, 편집, 저장, 취소, 재발급, 삭제, 운영자는 조회(URL 확인)만이다.
  문장을 고침: 최고관리자와 관리자는 생성, 편집, 저장, 취소, 재발급, 삭제를 할 수 있다.
             운영자는 조회(URL 확인)만 할 수 있다.
  ```
- 전부 쉼표로 바꾸는 순간 층이 무너져서 원래보다 읽기 어려워짐
- 검사 도구도 이 구분을 함
  - 단어만 바꾼 쪽은 걸리고, 문장을 나눈 쪽은 통과함

## 문자 두 가지를 구분함

- 가운뎃점 `·` U+00B7
  - 한글 맞춤법의 정식 문장 부호이고, 신문과 공문서에서 씀
  - 개발 문서에서는 문체가 튀므로 쓰지 않되, 층을 나누고 있었다면 문장을 나눠야 함
- 점 연산자 `⋅` U+22C5
  - 가운뎃점처럼 보이지만 수학 기호
  - 검색에 걸리지 않고 폰트에 따라 위치가 어긋남
- 이미 쓴 문서에서 찾기
  ```bash
  grep -rnP '\x{22C5}' <문서 경로>
  ```

## 설치

- Claude Code
  ```bash
  /plugin marketplace add eyedroot/marketplace
  /plugin install korean-style@eyedroot
  /output-style
  ```
- `/output-style`에서 `plain-korean`을 고르면 적용됨
- `~/.claude/settings.json`에 직접 적을 수도 있음
  ```json
  { "outputStyle": "korean-style:plain-korean" }
  ```

## 호환성

- output style은 Claude Code 기능이라 codex CLI에는 적용되지 않음
- 검사 스크립트는 python3만 있으면 어디서든 돌아감

## 사례를 늘릴 때

- 어휘 사례는 실제로 다시 나온 것만 넣음
  - 짐작으로 넣으면 목록만 길어지고, 목록이 길어지면 그것만 처리하고 멈추게 됨
  - 스무 개 안쪽으로 유지
- 팀과 제품이 쓰는 용어는 사례에 넣지 않음
  - v0.1.0에서 `전 트랙`을 `모든 요금제`로 바꾸라고 적었다가 걷어냄
  - 트랙은 콜러스가 실제로 쓰는 용어라 요금제로 바꾸면 뜻이 달라짐
  - 고칠 것은 용어가 아니라 그 앞에 붙은 압축이었음
