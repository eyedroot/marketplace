한국어로 출력할 때는 아래 지침을 지킵니다.

## 판단 기준은 하나입니다

단어를 고를 때마다 이렇게 물어봅니다.

**"이 단어를 옆자리 동료에게 말로 설명할 때 그대로 쓰겠는가."**

쓰지 않을 단어라면 바꿉니다. 어려운 단어인지 쉬운 단어인지를 따지는 것이 아니라, 실제로 자주 쓰는 단어인지를 따집니다. 뜻을 아는 단어라도 평소에 입으로 꺼내지 않는 단어라면 읽는 사람은 그 자리에서 한 번 멈춥니다.

뜻을 압축한다고 해서 글이 더 정확해지지는 않습니다. 짧은 단어 하나에 뜻을 몰아넣으면 읽는 사람이 그 뜻을 다시 풀어야 하므로 읽는 쪽의 부담만 늘어납니다.

## 어디에 적용하는가

적용합니다.

- 사용자에게 보여 주는 답변
- 계획 문서, 설계 문서, 조사 결과 보고
- Confluence, Notion, Obsidian에 쓰는 문서
- PR 설명, 이슈 설명

적용하지 않습니다.

- 코드, 변수명, 함수명
- 코드 주석, 커밋 메시지, 로그 문자열은 그 프로젝트의 기존 관례를 따릅니다
- 원문 그대로 옮겨야 하는 인용
- 오류 메시지, 명령어, 설정 키, 파일 경로

용어 자체를 번역하지는 않습니다. access token, PR, 키셋 페이지네이션처럼 이미 굳어진 말은 그대로 씁니다. 이 지침은 한국어 문장을 다듬으라는 것이지 외국어를 없애라는 것이 아닙니다.

## 어휘

### 영어 기술 문서를 그대로 옮기지 않습니다

영어에서 자연스러운 비유가 한국어에서는 어색하거나 불쾌하게 읽힙니다. 무슨 일이 벌어지는지를 그대로 씁니다.

- 고아 항목, 고아 레코드 → 참조가 끊긴 항목, 부모 행이 사라진 행
- 채널 1개를 보장한다 → 채널 1개를 만든다, 채널이 없으면 만든다
- 진실의 원천 → 기준이 되는 값, 기준이 되는 저장소
- 행복 경로 → 정상 흐름
- 온전성 검사 → 간단히 확인하기
- 최선 노력 방식 → 되는 만큼만 처리하는 방식

`고아`는 특히 쓰지 않습니다. 영어 orphan에는 없는 불편한 느낌이 한국어에는 남아 있습니다.

### 공문서에서 쓰는 한자어를 일상어로 바꿉니다

- 테이블 4개 신설 → 테이블 4개 생성
- 두 설정이 상이하다 → 두 설정이 다르다
- 검증 절차가 미비하다 → 검증 절차가 빠져 있다
- 캐시 갱신이 선행되어야 한다 → 캐시를 먼저 갱신해야 한다
- 오류는 타임아웃에 기인한다 → 오류는 타임아웃 때문에 생긴다
- 잔여 용량을 산출한다 → 남은 용량을 계산한다
- 사전에 확인한다 → 미리 확인한다
- 해당 항목에 한하여 → 그 항목만
- 마이그레이션을 수행한다 → 마이그레이션을 한다

### 없는 말을 만들지 않습니다

제품이 그렇게 부르지 않는 것에 영어 라벨을 붙이지 않습니다. 부를 이름이 없으면 한국어로 풀어서 설명합니다.

- 전 트랙 기능이라 → 모든 요금제에서 쓰는 기능이라, 어디서나 쓰는 기능이라
- 전 구간에 적용 → 처음부터 끝까지 적용

### 비유로 일반 명사와 동사를 대체하지 않습니다

- 분석의 흐름 → 분석의 방향
- 코드에 박아 둔다 → 코드에 적어 둔다
- 요청을 태워 보낸다 → 요청과 함께 보낸다

이미 굳어져서 바꾸면 오히려 어색한 말은 그대로 둡니다. 폴백, 롤백, 캐시 워밍이 여기에 해당합니다.

## 문장

### 명사를 늘어놓지 않고 조사와 어미를 붙입니다

명사만 이어 붙이면 짧아지기는 하지만 어떤 관계인지가 사라집니다.

- 지출 비용 추론 용도의 토큰 카운트 함수의 오류 상황에서 → 쓴 비용을 계산하는 토큰 카운트 함수에 문제가 생기면
- 권한 확인 누락 시 접근 허용 → 권한을 확인하지 않으면 접근이 허용됩니다

`의`를 겹쳐 쓰면 문장 성분이 사라지기 쉽습니다. 한 문장에 `의`가 세 번 넘게 나오면 다시 씁니다.

### 뜻이 있는 성분을 빼지 않습니다

- 그러면 경고가 붙습니다 → 그러면 이미 작업 중인 파일에도 경고 표시가 붙습니다

### 문장을 끝맺습니다

명사구나 연결어미로 문장을 끊지 않고 서술어로 끝냅니다. 제목, 목록 항목, 표 안에는 적용하지 않습니다. 구조화된 목록을 쓰는 다른 지침이 종결 방식을 따로 정해 두었다면 그쪽을 따릅니다.

## 문장 부호와 표기

- 나열은 쉼표로 합니다. 짝을 이루는 둘은 빗금도 괜찮습니다.
  - 생성·조회·수정·삭제 → 생성, 조회, 수정, 삭제
  - 가운뎃점(`·`, U+00B7)은 신문과 공문서에서 쓰는 부호라서 개발 문서에서는 문체가 튑니다.
  - 점 연산자(`⋅`, U+22C5)는 가운뎃점과 아예 다른 수학 기호입니다. 검색에도 걸리지 않으므로 어떤 경우에도 쓰지 않습니다.
- 엠대시(`—`)는 쓰지 않습니다. 앞뒤 관계를 너무 줄여 버립니다. 콜론이나 접속사로 바꿉니다.
- 영문 뒤에 오는 조사는 붙여 씁니다. 한글 맞춤법 제41항에 따라 조사는 앞말에 붙습니다.
  - collections 는, slug 가, NULL 이므로 → collections는, slug가, NULL이므로
- 이모지는 쓰지 않습니다.

## 내보내기 전에 확인합니다

1. 말로는 하지 않을 단어가 있는가
2. 영어 표현을 그대로 옮긴 자리가 있는가
3. 명사만 이어 붙인 구절이 있는가
4. 가운뎃점, 점 연산자, 엠대시, 이모지가 있는가
5. 영문 뒤 조사가 떨어져 있는가

문서를 파일로 저장했다면 이 플러그인의 `scripts/check_korean.py`로 같은 항목을 기계적으로 확인할 수 있습니다.
