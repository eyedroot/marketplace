## 공통 규칙

### 크기

- 폭은 900~950이 적당함. 옵시디언 본문 폭에서 잘리지 않고, 브라우저에서도 여유가 있음
- 높이는 내용에 맞춤. 시퀀스는 단계당 55~60을 확보하면 라벨이 겹치지 않음
- `viewBox`와 `width`/`height`를 같이 지정함. `viewBox`만 있으면 임베드 시 크기가 들쭉날쭉해짐
- 노트에서 폭을 줄이려면 `![[그림.svg|800]]`을 씀. SVG를 다시 만들 필요가 없음

### 글자 크기

SVG 안의 글자는 축소되면 같이 작아짐. 모바일에서도 읽히려면 12px 아래로 내려가지 않는 편이 안전함.

| 클래스 | 크기 | 쓰임 |
|---|---|---|
| `.head` | 12.5px bold | 참여자 이름, 패널 제목 |
| `.lbl` | 12.5px | 본문 라벨 |
| `.lbl-sm` | 11px | 화살표 설명 |
| `.lbl-xs` | 10px | 부연, 주석 |

### 색 배정

참여자가 셋 이상이면 **참여자마다 색을 부여**함. 그 참여자의 박스와 그가 보내는 화살표를 같은 색으로 묶으면, 읽는 사람이 "누가 무엇을 했는지"를 색으로 따라갈 수 있음.

`svg_scaffold.py`가 만드는 골격에는 `--r1`~`--r4`가 준비되어 있음. 위험·경고는 `--danger`를 씀. 배경이 필요하면 `-bg` 접미사(`--r1-bg`)를 씀.

## 비교형

"지금"과 "목표", "문제"와 "해결"을 대조할 때 씀. 좌우로 나누고, **대응되는 요소를 같은 y에 배치**하는 것이 핵심임. 그래야 눈이 좌우로 움직이며 차이를 잡아냄.

```
폭 920 기준
  좌 패널  x=8    w=418
  우 패널  x=482  w=430
  간격     44
```

패널 구분은 색과 선으로 함. 문제 쪽은 점선(`stroke-dasharray="4 3"`)에 위험색, 해결 쪽은 실선에 강조색을 주면 성격이 바로 읽힘.

```svg
<rect x="8" y="8" width="418" height="284" fill="var(--danger-bg)"
      stroke="var(--danger)" stroke-width="1" stroke-dasharray="4 3"/>
<text class="head" x="26" y="34" fill="var(--danger)">지금 방식</text>
<text class="lbl-xs" x="26" y="52" fill="var(--danger)">한 줄 요약</text>
```

패널 하단에 결과를 4줄 정도로 나열하면 대조가 선명해짐. 좌우 같은 y에 같은 개수로 두면 좋음.

```svg
<rect x="28" y="164" width="386" height="106" fill="none" stroke="var(--rule)"/>
<text class="lbl-sm" x="44" y="188" fill="var(--danger)">권한 전체가 넘어감</text>
<text class="lbl-sm" x="44" y="209" fill="var(--danger)">만료 없음</text>
```

## 시퀀스형

절차를 설명할 때 가장 많이 씀. 참여자별 세로 생명선에 번호 붙은 화살표를 그림.

### 좌표 설계

```
폭 950, 참여자 4명 기준
  레인 헤더   y=14, 높이 46, 폭 140
  레인 중심선 x = 100, 342, 584, 845     (균등 배치)
  생명선      y=60 부터 하단까지, 점선 opacity 0.55
  첫 단계     y=100
  단계 간격   55~60                      (라벨이 두 줄이면 60)
```

단계 간격을 55보다 좁히면 화살표 위 라벨과 아래 부연이 겹침. 단계가 10개를 넘으면 도해를 둘로 나누는 편이 읽기 좋음.

### 단계 하나의 구성

번호 원 + 화살표 + 위 라벨 + (필요시) 아래 부연. 번호 원은 **출발하는 참여자의 생명선 위**에 둠.

```svg
<circle cx="100" cy="100" r="9" fill="var(--r1)"/>
<text class="num" x="100" y="104" text-anchor="middle">1</text>
<line x1="112" y1="100" x2="334" y2="100" stroke="var(--r1)" stroke-width="1.8"
      marker-end="url(#a1)"/>
<text class="lbl-sm" x="223" y="92" text-anchor="middle" fill="var(--ink)">연결 버튼을 누른다</text>
<text class="lbl-xs" x="223" y="118" text-anchor="middle" fill="var(--r1)">부연 설명</text>
```

화살표 끝점은 목표 생명선보다 8px 앞에서 멈춤(`x2 = 342 - 8`). 화살촉이 생명선을 넘어가면 지저분해짐.

### 자기 자신에게 돌아오는 단계

내부 계산을 표현할 때 씀. 오른쪽으로 나갔다 돌아오는 갈고리 모양임.

```svg
<path d="M 354 148 h 40 v 26 h -40" fill="none" stroke="var(--r2)"
      stroke-width="1.8" marker-end="url(#a2)"/>
<text class="lbl-sm" x="404" y="146" fill="var(--ink)">난수를 만들고 해시한다</text>
```

### 강조하고 싶은 단계

선 굵기를 2.2로 올리거나, 부연을 위험색으로 적음. 전체를 굵게 하면 강조가 사라지므로 한두 곳만 씀.

## 구조형

시스템 구성과 경계를 보여줄 때 씀. 경계 박스(점선)로 "내부"와 "외부"를 나누는 것이 핵심임.

```svg
<!-- 외부 -->
<rect x="26" y="130" width="150" height="120" fill="var(--r2-bg)"
      stroke="var(--r2)" stroke-width="1.5"/>

<!-- 내부 경계: 점선으로 소유 범위를 표시 -->
<rect x="236" y="26" width="640" height="348" fill="none"
      stroke="var(--rule)" stroke-width="1.5" stroke-dasharray="6 4"/>
<text class="lbl-xs" x="252" y="46" fill="var(--ink-faint)">우리 내부 경계</text>
```

구성 요소 박스 안에는 이름, 기술 스택, 역할을 3층으로 씀. 구분선을 하나 넣으면 정보 층위가 잡힘.

```svg
<rect x="266" y="76" width="230" height="128" fill="var(--r3-bg)"
      stroke="var(--r3)" stroke-width="2"/>
<text class="head" x="381" y="102" text-anchor="middle" fill="var(--r3)">인증 서버</text>
<text class="lbl-xs" x="381" y="124" text-anchor="middle" fill="var(--r3)">Laravel 12</text>
<line x1="286" y1="136" x2="476" y2="136" stroke="var(--r3)" stroke-width="0.8" opacity="0.5"/>
<text class="lbl-xs" x="286" y="154" fill="var(--ink-soft)">역할 1</text>
<text class="lbl-xs" x="286" y="171" fill="var(--ink-soft)">역할 2</text>
```

관계선은 성격에 따라 구분함. 실선은 실제 요청 흐름, 점선은 참조나 신뢰 관계를 뜻하게 쓰면 일관성이 생김.

곡선이 필요하면 2차 베지어를 씀. 직선이 다른 박스를 관통할 때만 쓰고, 남용하면 따라가기 어려워짐.

```svg
<path d="M 180 210 q 200 130 410 100" fill="none" stroke="var(--r2)"
      stroke-width="1.8" marker-end="url(#a2)"/>
```

## 자주 겪는 문제

### 도해가 검은 박스로 보임

CSS 변수가 정의되지 않아 `fill`이 초기값(검정)으로 떨어진 것임. SVG 내부에 `<style>`로 변수를 정의했는지 확인함. 노트 본문에 인라인으로 넣었다면 옵시디언이 `<style>`을 제거하므로 파일로 분리해야 함.

### 글자가 세리프로 나옴

`<text>`는 문서 폰트를 물려받지 않음. SVG 내부 `<style>`에 `text{font-family:…}`를 넣음. 웹폰트는 CSP와 독립 로딩 때문에 못 쓰므로 시스템 폰트 스택을 씀.

### XML 주석 안에 하이픈 두 개

`<!-- var(--accent) -->`처럼 주석에 `--`가 들어가면 XML 파싱이 깨짐. 변수명을 주석으로 설명하려면 `<desc>` 요소를 쓰거나 표기를 바꿈.

### 화살표가 안 보임

`marker-end="url(#a1)"`가 가리키는 마커가 `<defs>`에 정의되어 있는지 확인함. 파일을 분리하면 마커 id는 파일마다 독립이라 충돌이 없고, 짧은 이름을 써도 됨.

### 배경이 노트 색과 안 맞음

SVG는 기본이 투명이라 노트 배경이 그대로 비침. 도해 영역을 구분하려면 배경 `rect`를 깔되, `var(--card)` 같은 변수로 두어 다크 모드에서도 맞게 함.

### 모바일에서 글자가 작음

폭을 줄이면 글자도 같이 줄어듦. 옵시디언 모바일에서 읽으려면 애초에 폭을 900 이하로 잡고 글자를 12px 이상으로 두거나, 도해를 둘로 나눔.
