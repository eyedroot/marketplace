## 콜아웃

HTML `<div>` 대신 쓰는 강조 박스. 테마 색이 자동 적용되고 접을 수도 있음.

```markdown
> [!info] 제목
> 본문

> [!warning]- 접힌 상태로 시작
> 하이픈을 붙이면 기본 접힘, 플러스는 기본 펼침

> [!tip]
> 제목을 생략하면 종류 이름이 제목이 됨
```

| 종류 | 색 | 쓰임 |
|---|---|---|
| `note` | 파랑 | 일반 메모 |
| `abstract` `summary` `tldr` | 청록 | 요약 |
| `info` | 파랑 | 배경, 목적 |
| `todo` | 파랑 | 할 일 |
| `tip` `hint` `important` | 청록 | 알아두면 좋은 점 |
| `success` `check` `done` | 초록 | 완료, 통과 |
| `question` `help` `faq` | 노랑 | 미결 사항 |
| `warning` `caution` `attention` | 주황 | 주의, 제약 |
| `failure` `fail` `missing` | 빨강 | 실패 |
| `danger` `error` | 빨강 | 위험 수준 |
| `bug` | 빨강 | 알려진 결함 |
| `example` | 보라 | 예시 |
| `quote` `cite` | 회색 | 인용 |

콜아웃 안에 표·코드블록·목록을 넣을 수 있음. 모든 줄 앞에 `>`를 붙임.

## 링크와 임베드

```markdown
[[노트 제목]]                    노트 연결 (백링크 생김)
[[노트 제목|보이는 텍스트]]        표시 이름 지정
[[노트 제목#섹션]]                특정 헤딩으로
![[노트 제목]]                   노트 내용을 그대로 삽입
![[그림.svg]]                   이미지·SVG 삽입
![[그림.svg|600]]               폭 600px로
![[문서.pdf#page=3]]            PDF 특정 쪽
[열기](attachments/원본.html)    첨부 파일 링크 (기본 앱으로 열림)
```

`![[...]]`는 vault 전체에서 파일명으로 찾음. 같은 이름의 파일이 여러 폴더에 있으면 예상과 다른 것이 잡힐 수 있으니, 접두사를 붙여 이름을 구분해 두는 편이 안전함(`oauth-fig1.svg`처럼).

## frontmatter

```yaml
---
title: 문서 제목
status: draft
created: 2026-07-28
tags:
  - 프로젝트명
  - 티켓번호
aliases:
  - 다른 이름
cssclasses:
  - wide-table
---
```

주의할 점:

- `tags`는 리스트로 쓰거나 `tags: [a, b]` 형태로 씀. 공백으로 구분하면 하나의 태그로 인식됨
- 날짜는 `YYYY-MM-DD`로 씀. 따옴표를 붙이면 문자열로 저장되어 날짜 정렬이 안 될 수 있음
- 값에 콜론이나 `#`가 들어가면 따옴표로 감쌈
- Obsidian MCP의 `write_note`를 쓸 때는 frontmatter를 **전용 파라미터로** 넘김. 본문 문자열에 YAML을 직접 넣으면 그대로 텍스트로 저장되어 태그가 인식되지 않음

## 읽기 모드에서 사라지는 것

Obsidian은 노트 안의 HTML을 렌더링하지만 아래는 보안상 제거함.

- `<style>` — 스타일이 전부 무효. CSS 변수를 쓰는 인라인 SVG가 검게 보이는 원인
- `<script>` — 실행되지 않음
- `on*` 속성 (`onclick` 등)

살아남는 것: 일반 태그(`<div>` `<span>` `<table>` `<details>` 등), `style="..."` 인라인 속성, `<iframe>`(유튜브 임베드가 이 방식).

즉 **인라인 `style` 속성은 되고 `<style>` 블록은 안 됨**. 색 몇 개만 필요하면 인라인 속성으로 해결할 수 있으나, 미디어쿼리와 가상클래스를 못 쓰므로 다크 모드 대응이 불가능함. 그래서 도해는 파일로 분리하는 편이 나음.

## 문법 함정

### HTML 블록 안의 빈 줄

HTML을 여러 줄 쓸 때 중간에 빈 줄이 있으면 마크다운 파서가 단락 구분으로 해석해 블록을 끊음. 그 뒤부터 태그가 텍스트로 노출됨. HTML을 쓸 수밖에 없다면 **빈 줄 없이 붙여 씀**.

### 구두점으로 끝나는 강조

닫는 `**` 직전이 구두점이고 직후에 문자가 붙으면 강조가 적용되지 않음(CommonMark 우측 플랭킹 규칙).

```markdown
정상: **권한 범위** 는          닫기 직전이 문자
정상: **강조**입니다             닫기 직전이 문자
깨짐: **권한 범위(scope)**는     닫기 직전이 ')'
깨짐: **끝났습니다.**그리고       닫기 직전이 '.'
```

괄호로 원어를 병기하는 한국어 문서에서 자주 걸림. 뒤에 공백을 넣거나 조사를 강조 안에 포함함.

### 표 안의 파이프

셀 내용에 `|`가 들어가면 `\|`로 escape하거나 인라인 코드로 감쌈.

### 목록 안의 코드블록

목록 항목 아래에 코드블록을 넣으려면 4칸(또는 목록 표시 너비만큼) 들여씀. 들여쓰기가 부족하면 목록이 끊김.

### 위키링크 안의 특수문자

`[[` `]]` `|` `#` `^`는 링크 문법으로 해석됨. 노트 제목에 이 문자를 넣지 않는 편이 안전함.

## vault 다루기

### 경로 찾기

```bash
ls ~/Library/Mobile\ Documents/iCloud~md~obsidian/Documents/
find ~ -maxdepth 4 -type d -name ".obsidian" 2>/dev/null
```

`.obsidian` 폴더가 있는 디렉터리가 vault 루트임.

### 첨부 파일

대상 노트와 같은 폴더의 `attachments/`에 두는 것이 일반적임. vault에 이미 다른 관례가 있으면 그것을 따름. 설정 > 파일 및 링크 > 첨부 파일 폴더 경로에서 확인할 수 있음.

### 쓰기 방법 선택

- 본문이 길면 파일시스템에 직접 씀. MCP 파라미터로 큰 문자열을 넘기는 비용이 큼
- MCP `write_note`를 쓸 때는 frontmatter를 전용 파라미터로 분리함
- 파일시스템에 직접 쓰면 Obsidian이 변경을 자동 감지해 즉시 반영함

### iCloud 동기화

iCloud vault는 파일 생성 후 동기화까지 시간이 걸림. 다른 기기에서 바로 안 보여도 정상임. 첨부 파일도 함께 동기화됨.

## CSS 스니펫

HTML 구조를 유지해야 할 때의 선택지. `<vault>/.obsidian/snippets/이름.css`에 두고 설정 > 외관 > CSS 스니펫에서 켬. 플러그인 설치가 필요 없음.

작성 규칙 두 가지가 중요함.

**컨테이너 클래스로 범위를 한정함.** 그러지 않으면 vault의 모든 노트에 적용됨.

```css
/* 나쁨: 전역 오염 */
h2 { font-size: 24px; }

/* 좋음: 특정 노트 안에서만 */
.my-guide h2 { font-size: 24px; }
```

**다크 모드는 `body.theme-dark`를 기준으로 함.** `prefers-color-scheme`은 OS 설정을 따르므로, OS는 라이트인데 Obsidian은 다크인 조합에서 어긋남.

```css
.my-guide { --ink: #14202e; }
body.theme-dark .my-guide { --ink: #dfe6e8; }
```

노트 쪽에서는 `cssclasses` frontmatter로 클래스를 붙일 수 있음.

```yaml
---
cssclasses:
  - my-guide
---
```

한계도 알아둘 것: 사용자가 토글을 켜야 하고, 스니펫이 동기화되지 않은 기기에서는 무효임. 그래서 기본 선택은 마크다운 네이티브가 나음.
